## mpvExTV 1.6.0 — 多声道音轨 HDMI 直通（含 Dolby Atmos）

本次是音频通路的一次大改：多声道音轨可以**原始压缩码流**经 HDMI / ARC 原样送给功放（AVR），
不再被电视下混成立体声。全部改动随 APK 一起编译（内核以 overlay 补丁形式注入），不需要另装任何东西。

### 新增

- **音频直通总开关**（设置 → 音频 → 音频直通），默认关闭。关闭时解码为 PCM 走电视扬声器。
- **直通策略**二选一：
  - **音质优先**：任何时候都保持码流直通；此时变速不会作用到音频（压缩码流无法变速），
    状态栏会提示「直通（变速未生效）」。
  - **速度优先**：速度 ≠ 1.0× 时自动退回 PCM，让 mpv 的变速真正生效；回到 1.0× 自动恢复直通，
    屏幕会短暂提示当前状态（直通 / PCM 下混）。
- 支持格式：AC3、E-AC-3（含 Dolby Atmos / JOC）、DTS、DTS-HD、TrueHD。

### 关键修复（内核层）

1. **绕过平台拒绝的 IEC61937 封装**：本机 HAL 不接受 `ENCODING_IEC61937`，旧的封装式直通必然回退 PCM。
   现在把**裸压缩码流**直接交给 AudioTrack（`ENCODING_E_AC3 / AC3 / DTS / DTS_HD / TRUEHD`），由 ARC 原样输出。
2. **压缩流字节精确**：AO 按 `sstride=4` 整块取数，而 E-AC-3 帧只保证 2 字节对齐；旧实现补零会注入垃圾、
   让平台解析器反复失步。改为跨包续传（`raw_buf` / `memmove` 保留余量），一字节不多一字节不少。
3. **采样率语义分离**：mpv 内部的「记账率」（= 码率 / 8 / 4）与平台要求的 codec 采样率（48000）分开处理。
   混用会让 AudioTrack 建不起来，进而静默回退 PCM —— 这是「一直显示立体声」的真因。
4. **音频钟按增量队列记账**：压缩轨落在 AudioFlinger 的 OFFLOAD 线程上，位置计数按 HAL 采样率前进。
   报告的延迟改为「写入累加、按平台位置递减」的增量模型，码率估计变化不再回头重算历史，
   从而消除 1.0× 状态下每隔一会儿一次的轻微卡顿和持续增长的丢帧。
5. **首播黑屏**：`force-window` 不再在 surface 创建时立刻设置 —— 那会让 mpv 抢在异步 OSD 窗口 attach
   之前打开 VO，报 `No Android OSD Surface` 并退化成软解。改为确认 `android-osd-wid` 后再开 VO，
   首个文件也要等 OSD 就绪后才 `loadfile`。

### 其它

- `/sdcard/mpv/mpv.log` 只在「设置 → 高级 → 详细日志记录」打开时写出，并在超过 32 MiB 时自动清理，
  不再无限增长（上一版诊断期间曾涨到约 900 MB）。
- 版本号 1.5.1 → 1.6.0。

### 已知限制

- 直通能力取决于电视的 HDMI 输出。本机（TCL / 雷鸟 R635C，无 eARC）的 ARC 口只支持 AC3 与 E-AC-3，
  所以 DTS / DTS-HD / TrueHD 会被平台拒绝，只能软解。
- ARC 下的 PCM 只有 2 声道，因此「速度优先」在非 1.0× 时的多声道会被下混为立体声。
- 内核基线仍锁定 FongMi/mpv `f68eb0a699`，本次音频改动以内核 overlay 补丁的形式加入，未更换内核。

## mpvExTV 1.6.1 — 倍速播放稳定性与音频下混修正

本次是 1.6.0 之后的维护版本，重点解决**高倍速播放大文件时频繁停顿**的问题，并补齐变速切换立体声时的低音内容。
全部改动已在电视（TCL / 雷鸟 R635C，Android 9）实机验证通过。HDMI / ARC 多声道直通能力保持不变。

### 关键修复

1. **1.8× 播放 20GB 级片源不再频繁停顿（等缓存）**
   系统报告内存吃紧时，`onTrimMemory()` 原本会把 `demuxer-max-bytes` 在运行时**改成 8 MiB**、把回退缓存清零并丢弃全部缓冲，
   而且之后**没有任何恢复逻辑** —— 一次触发，整个播放内核生命周期内缓存就一直是 8 MiB（约只够 1.6 秒），
   于是每次 `cache-pause` 都要停 3 秒，表现为周期性卡顿。
   现在只执行 `drop-buffers` 释放内存，**不再改动用户设定的缓存上限**；成功路径也补上了日志，便于以后观测。
   顺带说明一个反直觉现象：缓存设得越大（例如 300+ MiB）越容易把内存顶到 `TRIM_MEMORY_RUNNING_CRITICAL`，
   因而越容易触发这段逻辑、反而更顿 —— 所以单纯加大缓存并不能解决该问题。

2. **变速切成立体声时不再丢失低音声道内容**
   5.1 / 7.1 音轨在速度 ≠ 1.0× 时会退回 PCM 下混，而 ffmpeg/libswresample 的默认下混矩阵会**直接丢弃 LFE**。
   现在由应用按 ITU-R BS.775 矩阵自行合成 `af` 链，把 LFE 以 0.5 系数折入左右声道；
   左右声道的声像关系保持不变。同时顺手修掉了「反转立体声」会覆盖音量归一化滤镜的老问题。
   注意：这只是让低音内容**混进左右声道**播放，不会还原出 2.1 / 独立低音炮效果；1.0× 下的直通路径不受影响。

3. **退出播放后不再长期占用后台内存**
   按 Home / 离开播放器且并未处于后台播放时结束媒体前台服务，避免 app 退出后仍常驻。

### 播放状态栏

- `ratio`（SMB 速率 / 码率）的分母改为**源码率 × 倍速**。此前 1.8× 下读数是按 1× 口径算的，会虚高；
  现在要 ≥ 1.8（并留出网络抖动余量）才算带宽真正够用。
- 「显示状态栏」下新增二级开关 **只在暂停播放时显示**（默认关闭）：开启后平时完全隐藏，
  仅在用户暂停或 mpv 等缓存（`paused-for-cache`）时出现 —— 等缓存正是最需要看 BUF / ratio 的时刻。
  隐藏期间连轮询都停掉，不产生额外开销。

### 构建 / 维护

- 修复 CI 原生依赖 `uchardet` 下载失败：改用 gitlab.freedesktop.org 官方源并校验 gzip、失败重试；
  重试时清理完整的 `buildscripts/deps`，避免半下载的包反复毒化后续构建。
- 修复通过 Git Data API 推送脚本时丢失可执行位的问题，CI 现在统一给 `buildscripts/*.sh` 补 `chmod +x`。
- 构建机固定为 `ubuntu-24.04`。

### 其它

- 版本号 1.6.0 → 1.6.1（versionCode 160 → 161）。
- 发布包含 `armeabi-v7a`（32 位电视）与 `arm64-v8a` 两个 ABI；日常测试构建仍只出 v7a。

### 已知限制

- 直通能力取决于电视的 HDMI 输出。本机（TCL / 雷鸟 R635C，无 eARC）的 ARC 口只支持 AC3 与 E-AC-3，
  DTS / DTS-HD / TrueHD 会被平台拒绝，只能软解。
- 缓存上限等设置只在播放器初始化时读取一次，**改完设置需彻底结束 app 进程再重开**才会生效；
  若关闭「低内存模式」，缓存上限会走固定值分支，用户自定义值不起作用。
